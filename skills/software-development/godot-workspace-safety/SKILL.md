# Godot 工作区保护与外派隔离规范

本 Skill 规定了在向外部编程代理（如 Codex CLI）外派任务或执行自动化修改时的强制安全防线。

## 核心防御原则

1. **分级处理：难度判定与外派边界**：
   - **复杂与强耦合修改（外派 Codex CLI）**：涉及跨多目录、多文件强耦合、底层架构重构、复杂算法或大规模业务逻辑变更时，必须交由专业 Coding Agent（Codex CLI）执行。
   - **简单与局部单文件修改（兰芳直接处理）**：对于低耦合、局部单文件修复、明确简单的场景属性微调（如坐标/显隐修正）或确定性的 Git 冲突标记消除，可直接由兰芳处理，避免过度转交增加延迟与工具链依赖。
   - **Codex 不可用时的降级分支**：若外部编码代理服务挂起或不可用（如本地代理 503），在经用户确认后可直接由兰芳接管局部安全修改。手写/修补 `.tscn` 时须严防损坏 UID、ExtResource ID 映射及反序列化依赖链。

2. **TSCN 节点清理与行尾符陷阱**：
   - **换行符陷阱（CRLF vs LF）**：在 Windows 上使用正则或多行匹配时，直接跨行匹配可能因 `\r\n` 导致正则范围识别失败（如未成功替换或整块跳过）。处理 `.tscn` 时优先使用基于行遍历的状态机（检查 `[node `、`[editable ` 等声明头），并在文件写入时保持统一换行。
   - **子节点连带与 editable path 清理**：删除父节点（如 `ReturnArtAlignment`）时，其下的所有子节点块（`parent="ReturnPhase/ReturnArtAlignment"`）以及文件末尾的 `[editable path="..."]` 引用必须同步剔除，否则场景载入会报孤儿节点或路径缺失错误。
   - **物理层与逻辑层保护**：清理视觉装饰节点时，严禁误触物理层（如 `OutwardTileMap` / `ReturnTileMap`）及逻辑判定所依赖的节点。

2. **严禁未经排查直接回滚工作区文件**：
   - 遇到报错或编辑器异常时，**绝对禁止**擅自执行 `git checkout -- <file>`、`git restore <file>`。
   - 原因：用户可能在编辑器或本地有未保存、未暂存的关卡摆放与调试改动，直接 checkout 会永久抹杀用户成果。
   - 异常排查标准步骤：
     1. 首先运行 `git status` 与 `git diff` 确认当前工作区中哪些是用户未提交的修改，哪些是自动工具产生的修改。
     2. 如果需要撤销操作，必须先通过单独的备份（或 stash）保护用户未提交内容，或仅定点还原自身产生的差异。
     3. 必须先定位根因并向用户报告，而非一键重置破坏现场。

3. **合并冲突先做语义核验，再决定修复范围**：
   1. 先用 `git show --remerge-diff --format= <merge>` 列出 Git 的实际文本冲突文件；它只说明自动合并无法决定，不等于每个文件都是功能缺陷。
   2. 对每个场景冲突分别比较两侧父提交与最终合并结果，检查节点树、`ExtResource`/`SubResource`、`NodePath`、脚本引用和宿主场景覆写；不要只按“选了哪一边”判断丢失功能。
   3. 把运行时存档、用户本地设置和可再生成数据从玩法/场景修复范围中分离。除非有明确复现或产品要求，它们不是回滚或功能修复的依据。
   4. 修复前确认候选节点是否已存在于最终场景。场景资源 ID 重排、节点自动增补或另一侧等价实现会制造“看似丢失”的假象；重复添加会导致双重视觉、重复碰撞或错误引用。
   5. 只有确定最终合并确实破坏了功能时，才在隔离 worktree 中制作最小追加修复提交；已推送共享分支默认不重写历史，也不整批 revert 含多项功能的合并提交。

4. **外派前强制独立快照与外派后范围审计**：
   - 调用外部代理前，先从真实仓库根目录记录 `git status --short`，再对所有已修改、已暂存和未跟踪文件制作仓库外快照；快照必须保留相对路径，并覆盖未跟踪素材，不能只备份目标文件。
   - 可复用的 Git Bash 做法：`{ git ls-files -m -o --exclude-standard -z; git diff --cached --name-only -z; } | sort -zu | tar --null -T - -cf "$TMPDIR/workspace_<timestamp>.tar"`。快照放在 Hermes scratch/系统临时目录，不得写回仓库。
   - 外派 Prompt 必须给出明确的允许修改路径白名单。代理完成后，将快照内每个文件的哈希与当前文件比较，并结合 `git status --short`、目标路径 `git diff --check` 审计新增和改动；不要仅相信代理自述的修改范围。
   - 若发现白名单外变化，只从外派前快照定点恢复这些文件；保留白名单内成果及用户原有改动。恢复后再次执行哈希比较，结果应只剩预期目标文件。
   - 严禁假设用户工作区干净或已保存，也不要用整仓 stash/pop 替代定点恢复；混合工作区中整仓恢复容易覆盖用户在代理运行期间产生的新改动。

5. **指令中显式禁止破坏性操作**：
   - 派发给外部代理的任务 Prompt 中必须明确列出安全边界：禁止执行 `git checkout -- .`、`git reset --hard`、`git clean -fd` 等操作。

6. **仓库级 Agent 指令文件检查与恢复**：
   1. 先用 `git rev-parse --show-toplevel` 取得真实仓库根目录；不要把当前 Godot 工程子目录误当仓库根目录。
   2. 从仓库根目录检查大小写及单复数变体（重点包括 `AGENTS.md`、`AGENT.md`），并确认位于父级仓库根目录的文件是否仍覆盖子目录工程。文件已存在且可读时，不修改。
   3. 若工作区缺失，先检查 `HEAD` 是否仍跟踪该路径：若是，仅恢复该文件，避免影响其他未提交改动。
   4. 若 `HEAD` 中也不存在，再从当前分支祖先链定位该路径最后存在的提交；只有当前分支找不到时才扩展到 `--all`。恢复“删除前最近版本”，不要凭名称相似度选任意历史版本。
   5. 恢复前运行 `git status --short`，恢复后核对目标文件内容与 `git diff -- <path>`；不得顺带清理或覆盖其他工作区改动。
   - **路径陷阱**：在仓库子目录中搜索只会漏掉仓库根目录的指令文件，而 Git 的对象路径又以仓库根为基准；文件系统检查与历史查询必须统一到 `--show-toplevel` 返回的位置。

7. **继承包装场景的兼容迁移**：
   - 当关卡大量实例化一个继承自通用组件的包装场景时，优先修改包装场景继续继承新版通用组件，保留既有根节点类型、碰撞层、遮罩、位置、缩放和导出参数；不要要求用户重新实例化或重调物理层。
   - 清理旧视觉实现时，同时检查包装场景本身和关卡实例中的子资源覆写。只删除旧视觉节点、隐藏覆写与已无引用的资源声明；不得触碰逻辑、碰撞和实例变换。
   - **先确认旧节点是否仍被实例覆写**：继承场景删除子节点后，宿主 `.tscn` 可能保留该节点的覆写块或脚本资源；遗漏会造成孤儿覆写、旧视觉继续绘制或资源残留。

8. **编辑器并发写入防护**：
   - Godot 编辑器打开场景时，外部修改可能被编辑器内存中的旧版本回写覆盖。每次运行 headless 导入/验证后，重新读取目标文件并检查 `git diff`；不要仅凭补丁工具成功就宣称落盘。
   - 若目标文件被外部改写，基于最新内容重新做一次定点修改并再次验证；不要循环覆盖整个场景文件。

9. **编辑中场景物理隔离与松耦合通信**：
   - 当宿主引擎（Godot）正处于打开编辑状态时，新增需求一律优先封装为**独立小文件夹下的全新组件场景 (.tscn)**。
   - 严禁直接让外部工具修改或覆盖正在被编辑器打开的关卡场景文件。
   - 场景间机关与触发器联动优先使用全局事件总线（如 `SignalBus` 的 `trigger_channel` / `output_channel`）解耦通信，避免在 `.tscn` 文本中手动绑定跨节点 NodePath 导致解析崩溃。
